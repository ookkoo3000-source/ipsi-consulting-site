# 콘텐츠 작성 지침 (2026-10-15 감사 이후 확립)

이 문서는 2026-10-15 콘텐츠 품질 감사에서 발견된 문제들을 다시 만들지 않기 위한
영구 지침이다. 새 블로그 글을 생성하거나 기존 글을 수정할 때마다 이 문서를 읽는다.
`_tools/claim_lint.py`는 이 지침을 코드로 만든 **보조 탐지 도구**이며, 통과했다고
사실이 검증됐다는 뜻은 아니다 (아래 "claim_lint.py 사용법" 참고).

## 1. 왜 이 문서가 존재하는가

이전 글들에는 다음과 같은 문제가 반복적으로 있었다:
- 실재하지 않는 학교 이름을 캐주얼 웹 검색만으로 "가상의 학교"로 오판하거나,
  반대로 존재하지 않는 학교 이름을 그대로 써서 발행함.
- 특정 학교·지역의 "출제 경향", "난이도", "학원 밀집도", "채점 기준표" 등을
  마치 실제로 조사한 것처럼 서술함 (실제로는 그런 데이터를 보유하지 않음).
- "~로 알려져 있다", "~로 정평이 나 있다" 같은 근거 없는 평판성 문장.
- FAQ 질문 자체가 "OO고등학교 내신이 많이 어렵다고 하는데"처럼 근거 없는 전제를
  깔고 시작하는 경우 (답변만 고치면 질문의 전제가 그대로 남는다).
- 운영자 내부 메모(발행 체크리스트 등)가 공개 페이지에 그대로 노출됨.
- 자동화 스크립트로 문장을 지울 때 조사(은/는/이/가/을/를)가 안 맞게 되거나,
  문장이 중간에 끊겨 의미 없는 파편이 남는 경우.
- 같은 FAQ가 화면(HTML)과 JSON-LD(FAQPage)에 따로 들어있어, 한쪽만 고치고
  다른 쪽은 그대로 두면 눈에는 안 보이지만 구조화 데이터가 거짓말을 하게 됨.

## 2. 학교명을 쓰기 전에 반드시 확인한다

- 공식 소스는 **NEIS Open API** 하나다: `https://open.neis.go.kr/hub/schoolInfo?SCHUL_NM={학교명}&Type=json` (키 불필요).
- 응답에 `"schoolInfo"` 키가 있으면 존재, `"RESULT":{"CODE":"INFO-200",...}`면
  "정확히 그 이름으로는 없음" — **존재하지 않는다는 뜻이 아니다.** 지역명으로
  부분 검색(예: `SCHUL_NM=칠곡`)해서 그 지역에 해당 레벨(고등/중/초) 학교가
  정말 없는지 추가로 확인한 뒤에만 "이 지역에 이 레벨 학교가 없다"고 판단한다.
- 캐주얼 웹 검색으로 "그런 학교 없다"고 결론 내지 않는다 (과거 부산진고등학교,
  대덕고등학교를 웹 검색만으로 가상의 학교로 잘못 판단한 사례가 있었다).
- 학교명이 확인되지 않으면: 다른 학교 이름으로 바꾸지 말고, 사용자에게 보고하거나
  지역 기반 글("OO 지역 수학과외" 등)로 전환하되 — 전환 전에 이미 같은 지역·같은
  대상(학년대)의 글이 있는지 먼저 확인한다. 중복되면 전환하지 않고 보류를 보고한다.

## 3. 써도 되는 것 / 쓰면 안 되는 것

**써도 된다 (일반적인 학습 조언, 특정 대상에 귀속되지 않음):**
- "서술형 문제는 부분 점수가 있어도 작은 실수로 감점되는 경우가 많다."
- "함수·수열은 고등 수학에서 다른 단원과 연결되는 기초 개념이다."
- "1:1 수업은 학생의 취약점을 실시간으로 파악하기 쉽다."
- 상상코칭 프로그램 설명 + 반드시 포함: "이는 프로그램의 누적된 성과이며 개별
  학생의 성적 향상이나 합격을 보장하는 것은 아니다."
- 방문/화상 수업 중 선택 기준 (일반적인 장단점 비교).

**쓰면 안 된다 (특정 학교·지역에 대한 근거 없는 사실 주장):**
- "OO고등학교는 서술형 비중이 높다 / 변형 문제가 까다롭다 / 내신이 어렵기로
  유명하다" — 그 학교의 실제 시험을 분석한 적이 없다.
- "OO 지역 학원은 밀집도가 높다/낮다", "OO 지역 학교들은 경쟁이 치열하다" —
  확인한 적 없는 지역 환경 주장.
- "OO고등학교만의 독특한 출제 성향을 분석했다", "OO고 기출문제를 확보하고
  있다" — 실제로 특정 학교의 기출문제를 사전에 입수해 제공하지 않는다. 이런
  질문이 FAQ에 있다면 답은 반드시 "특정 학교의 기출문제를 미리 입수해 제공하는
  것은 아니며, 학생이 가진 교과서와 학교 진도에 맞춰 수업을 구성한다"는 식의
  정직한 답변이어야 한다.
- "~로 알려져 있다", "~로 정평이 나 있다" 같은 출처 없는 평판 문장.
- 확인되지 않은 서비스: 학생의 시험지를 학교에서 직접 확인·검토, 오답을 유형별로
  자동 분류, 채점 기준표 기반 첨삭, 정밀 진단 검사, 학습 플래너 제공, 전자 칠판
  실시간 첨삭 — 이런 표현은 실제로 그 서비스를 제공한다고 확인되기 전까지 쓰지
  않는다.
- **FAQ 질문 자체의 전제도 확인한다.** "OO고 내신이 어렵다고 하는데 어떻게
  대비하나요?"처럼 질문이 근거 없는 전제를 깔고 있으면, 답변만 고치는 게 아니라
  질문 자체를 "OO고 내신은 어떻게 대비하나요?"처럼 중립적으로 바꾼다.

## 4. 글을 쓸 때 지켜야 할 기술적 규칙

- **FAQ는 항상 두 곳에 있다**: 화면에 보이는 `<div class="faq">` 블록과
  `<script type="application/ld+json">`의 `FAQPage.mainEntity`. 질문이든 답변이든
  한쪽을 고치면 반드시 다른 쪽도 똑같이 고친다. 글자 하나까지 완전히 동일해야
  한다. 발행 전에 아래 체크를 실행한다:
  ```python
  import re, json
  h = open(path, encoding='utf-8').read()
  visible = re.findall(r'<div class="faq">\s*<h3>([^<]*)</h3>\s*<p>([^<]*)</p>', h)
  scripts = re.findall(r'<script type="application/ld\+json">(.*?)</script>', h, re.S)
  faq_json = [d for s in scripts for d in [json.loads(s)] if d.get('@type') == 'FAQPage']
  pairs = [(m['name'], m['acceptedAnswer']['text']) for m in faq_json[0]['mainEntity']]
  assert visible == pairs
  ```
- **지역명으로 학교명을 대체할 때 조사(助詞)를 조심한다.** "강북고등학교는" →
  "강북 지역은"으로 바꾸면 "은/는"은 맞지만, 글 전체에 흩어진 "강북고등학교가",
  "강북고등학교를" 등은 전부 따로 확인해야 한다. 가장 안전한 방법은 치환 대상
  뒤에 항상 "지역"이라는 완충 명사를 붙이는 것이다 — "지역"은 받침 'ㄱ'으로
  끝나는 고정된 발음이므로, 그 뒤에 오는 조사는 원래 단어가 무엇이었든 항상
  문법적으로 맞다. 치환 전에 원래 단어 뒤에 어떤 글자가 오는지 전부 `grep`으로
  확인하고, "로"처럼 받침에 따라 "으로"로 바뀌어야 하는 조사가 있으면 그 문장은
  통째로 다시 쓴다.
- **문장을 통째로 지울 때 태그 균형을 깨지 않는다.** `<strong>...</strong>` 중간을
  자르면 태그가 깨진다. 지우기 전에 태그를 토큰 단위로 나눠서, `<strong>` 구간은
  절대 중간에서 자르지 않는다. 지운 뒤에는 반드시 `<div>`, `<h3>`, `<strong>`,
  `<li>` 개수가 열고 닫는 태그 수가 일치하는지 확인한다.
- **문장 일부만 지우고 나머지를 남기면 안 된다.** "~풀이법을 ...을 통해 대비합니다"처럼
  앞부분이 사라진 문장이 남으면 바로 눈에 띄는 어색한 문장이 된다. 지울 대상이
  문장의 일부라면, 남는 부분이 그 자체로 완전한 문장인지 반드시 확인한다. 애매하면
  문장 전체를 자연스럽게 다시 쓴다.
- **블로그 목록(blog.html)의 카드를 스크립트로 수정할 때**, `<article class="article">...</article>`
  전체를 `re.findall`로 쪼갠 뒤 href로 정확히 하나의 카드를 찾아서만 교체한다.
  `re.search`에 비탐욕(`.*?`) 패턴을 쓰더라도 시작 위치가 문서 맨 앞 `<article>`로
  잡히면 잘못된 카드까지 통째로 덮어쓸 수 있다 (과거 실제로 발생한 버그).
  수정 후 반드시 `<article>` 개수가 수정 전과 같은지 확인한다.

## 5. 재사용 가능한 글 생성 프롬프트

새 학교별/지역별 블로그 글을 쓸 때 아래 틀을 그대로 사용한다. `{...}`는 채워야 할 값.

```
{학교명 또는 지역명}의 {과목} 과외를 주제로 블로그 글을 작성해줘.

사실 확인:
- 학교명을 쓸 경우, 먼저 NEIS Open API로 그 학교가 실제로 존재하는지,
  정확한 이름과 소재지가 맞는지 확인했다. (확인 결과: {NEIS 조회 결과 요약})
- 이 학교/지역에 대해 내가 실제로 아는 것은 없다. 출제 경향, 난이도, 학원 환경,
  기출문제 확보 여부에 대해 어떤 것도 사실처럼 쓰지 않는다.

써야 할 내용:
- 과목에 대한 일반적이고 유용한 학습 조언 (서술형 대비, 개념 학습법, 오답 관리 등)
  — 이런 조언은 특정 학교에 귀속시키지 않고 "고등학교 {과목} 내신에서는..." 처럼
  일반화해서 쓴다.
- 1:1 방문/화상 수업의 일반적인 장단점 (학생 성향에 따른 선택 기준).
- 상상코칭 프로그램 소개 — 반드시 "프로그램의 누적된 성과이며 개별 학생의 성과를
  보장하지 않는다"는 문장을 포함.
- FAQ 3개: 수업 방식(방문/화상) 선택, 상상코칭 프로그램 관련 질문은 괜찮다.
  "그 학교/지역 시험이 어렵다는데" 식으로 근거 없는 전제를 까는 질문은 쓰지 않는다.
  "기출문제를 확보하고 있나요?" 같은 질문을 쓴다면 답은 반드시 정직하게
  "특정 학교의 기출문제를 미리 입수해 제공하는 것은 아니며, 학생이 가진 교과서와
  학교 진도에 맞춰 수업을 구성한다"는 식으로 답한다.

형식:
- FAQ는 화면(<div class="faq">)과 JSON-LD(FAQPage)에 글자 하나까지 동일하게 넣는다.
- 작성 후 python3 _tools/claim_lint.py blog/{파일명}.html 을 실행하고, 걸리는
  항목이 있으면 왜 걸렸는지 하나씩 판단해서 고치거나 (일반화된 조언이면 괜찮을 수
  있음) 수정한다.
```

## 6. claim_lint.py 사용법과 한계

```
python3 _tools/claim_lint.py blog/새파일.html
```

- 이 스크립트는 **의심되는 표현을 찾는 보조 도구**다. 패턴에 안 걸렸다고 해서
  "사실 검증이 끝났다"는 뜻이 아니다. 패턴에 없는 새로운 방식의 근거 없는
  주장은 얼마든지 통과할 수 있다.
- 패턴에 걸렸다고 해서 무조건 삭제해야 하는 것도 아니다. 일반화된 학습 조언
  (예: "서술형은 감점이 많다")은 걸릴 수 있지만 유지해도 된다 — 학교/지역에
  귀속되지 않은 일반적 사실이기 때문이다. 반면 "OO고등학교는 서술형이 많다"처럼
  특정 대상에 귀속되면 반드시 고친다.
- 발행 전 마지막 단계로 실행하고, 출력에 뜨는 각 줄을 사람이 직접 읽고 판단한다.
